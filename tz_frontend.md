# Часть 2. Техническое задание: Веб-клиент (React + TypeScript)

## 2.1. Общие сведения и архитектура

**Цель MVP:** веб-клиент для мессенджера `xam`, который работает с бэкендом FastAPI
(`https://github.com/Macson2023/xam_backend`) и поддерживает регистрацию, вход, поиск
пользователей, личные диалоги, обмен текстовыми сообщениями в реальном времени, статусы
`online/offline` и индикатор «печатает».

**Стек:**

- React 19 + TypeScript (strict)
- Vite 7 (dev-сервер, сборка, proxy для REST и WebSocket)
- Нативный `fetch` и браузерный `WebSocket` (без сторонних HTTP/UI-библиотек)
- CSS-переменные, адаптивная вёрстка, тёмная тема
- Хранение access-токена в `localStorage`

**Архитектура:**

```
src/
  api/            # типы контракта бэкенда и HTTP-клиент
  auth/           # AuthContext: токен, профиль, вход/регистрация/выход
  hooks/          # useRealtime (WS) и useMessenger (состояние мессенджера)
  components/     # экраны и UI-компоненты
  lib/            # форматирование дат, merge/dedupe сообщений, UUID
```

Слой `useMessenger` инкапсулирует всю работу с API и WebSocket, компоненты остаются
презентационными. Это позволяет заменить транспорт или добавить роутинг без переписывания UI.

## 2.2. Функциональные требования

### 2.2.1. Аутентификация

- Экран входа и регистрации с переключением режимов.
- Регистрация: `username` (3–32, `[A-Za-z0-9_]`), пароль (8–72), отображаемое имя (1–64).
- Клиентская валидация до запроса, вывод серверных ошибок (`{ "detail": "..." }`).
- Успешный вход/регистрация сохраняют JWT и профиль, приложение открывает мессенджер.
- При старте приложения токен проверяется через `GET /api/v1/users/me`.
- При `401` (истёкшая сессия) токен удаляется и показывается уведомление.
- Выход очищает сессию и возвращает на экран входа.

### 2.2.2. Профиль и поиск

- В сайдбаре отображаются `display_name`, `@username` и аватар текущего пользователя.
- Поиск пользователей по `username` с debounce 300 мс и отменой устаревших запросов.
- Пустой результат, состояния загрузки и ошибки поиска.
- Кнопка «Написать» создаёт или возвращает существующий личный диалог и открывает его.

### 2.2.3. Диалоги

- Список диалогов: аватар, имя, превью последнего сообщения (`Вы:` для своих),
  время активности, счётчик непрочитанных, индикатор «печатает…».
- Сортировка по времени последней активности (как на бэкенде).
- Активный диалог подсвечивается, счётчик непрочитанных сбрасывается.
- Пустое состояние с подсказкой, как начать диалог.

### 2.2.4. Сообщения

- История загружается страницами по 50 сообщений (cursor-based пагинация `before`).
- Кнопка «Показать более ранние» с сохранением позиции скролла.
- Новые сообщения показываются в хронологическом порядке, разделители по дням.
- Отправка по `Enter`, перенос строки — `Shift+Enter`, автовысота поля, лимит 4000 символов.
- Оптимистичная отправка с `client_message_id` (UUID v4) и статусами:
  отправляется → отправлено → прочитано; при ошибке — «Повторить» (идемпотентный retry).
- Дедупликация по `id` и `client_message_id` (сообщение не дублируется, когда приходит
  и ответ REST, и событие WebSocket).
- При открытии диалога и при входящем сообщении в открытом диалоге вызывается
  `POST /api/v1/chats/{chat_id}/read`.
- Автопрокрутка вниз, только если пользователь находится у нижней границы; при чтении
  истории позиция не сбивается.

### 2.2.5. Realtime

- Подключение `ws://<host>/ws?token=<jwt>` с валидацией токена на сервере.
- Обработка серверных событий: `new_message`, `user_status`, `typing`, `error`, `pong`.
- Отправка `ping` каждые 25 секунд, `typing` — с троттлингом 2 секунды и сбросом через 2,5 с.
- Автопереподключение с экспоненциальной задержкой (1–15 с), повторное подключение
  при восстановлении сети, обновление чатов и открытого диалога после реконнекта.
- Код закрытия `1008` (невалидный токен) завершает сессию.
- Индикатор состояния соединения в сайдбаре и баннер при потере связи.

### 2.2.6. Присутствие

- `user_status` обновляет зелёный индикатор у собеседника в списке и шапке чата.
- При `offline` список чатов обновляется, чтобы показать актуальный `last_seen`.
- Если статус ещё не получен, используется `last_seen` («был(а) в сети …»).
  Бэкенд сообщает только переходы статуса, поэтому для собеседника, который был онлайн
  до подключения клиента, статус может оставаться неизвестным до следующего перехода.
- Активность собеседника (входящее сообщение или `typing`) дополнительно помечает его
  онлайн — это компенсирует отсутствие снимка присутствия в API.

## 2.3. Интеграция с бэкендом

Базовый префикс: `/api/v1`. Ошибки — `{ "detail": "..." }` с HTTP-статусом.

| Метод | Путь | Использование |
| --- | --- | --- |
| POST | `/auth/register` | Регистрация, возвращает JWT и профиль |
| POST | `/auth/login` | Вход, возвращает JWT и профиль |
| GET | `/users/me` | Проверка токена и профиль |
| GET | `/users/search?q=` | Поиск собеседника |
| GET | `/chats` | Список диалогов |
| POST | `/chats` | Создать/получить диалог по `participant_id` |
| GET | `/chats/{id}/messages?limit=&before=` | История сообщений |
| POST | `/chats/{id}/messages` | Отправка с `content` и `client_message_id` |
| POST | `/chats/{id}/read` | Отметить входящие прочитанными |
| WS | `/ws?token=` | События `new_message`, `user_status`, `typing` |

**Режимы подключения:**

- **Dev (по умолчанию):** фронтенд на `http://localhost:5173`, Vite проксирует `/api` и `/ws`
  на `http://localhost:8000`; CORS не задействован.
- **Прод, same-origin:** статика раздаётся nginx, который проксирует `/api` и `/ws` на
  `BACKEND_ORIGIN`.
- **Прод, разные домены:** при сборке задаются `VITE_API_URL` и `VITE_WS_URL`, а на бэкенде
  `CORS_ORIGINS` дополняется доменом фронтенда.

## 2.4. Нефункциональные требования

- **Адаптивность:** две панели на десктопе, переключение «список ↔ чат» на мобильных,
  поддержка `safe-area-inset` и `100dvh`.
- **Состояния:** скелетоны/спиннеры загрузки, пустые состояния, ошибки с повтором,
  баннер потери соединения, индикаторы отправки и ошибок.
- **Доступность:** семантические кнопки, `aria-label`, `role="status"/"alert"`,
  фокус-стили, навигация с клавиатуры.
- **Производительность:** debounce поиска, отмена запросов через `AbortController`,
  локальные обновления состояния без полной перезагрузки, сборка ~260 КБ JS (~81 КБ gzip).
- **Безопасность:** пароль не хранится на клиенте; JWT передаётся в `Authorization: Bearer`
  и в query-параметре WebSocket; при `401`/`1008` сессия завершается.
- **Ограничения MVP:** только личные диалоги, текстовые сообщения, без вложений и звонков;
  статусы прочтения и присутствия определяются контрактом бэкенда.
